# mbstring and iconv

PHP's `mb_*` and `iconv*` functions for Phera: strings as characters in a
named encoding instead of as bytes.

```php
strlen('Straße');                                  // 7
mb_strlen('Straße');                               // 6
mb_strtoupper('Straße');                           // "STRASSE"
mb_substr('日本語テキスト', 2, 3);                   // "語テキ"
mb_convert_encoding('é', 'ISO-8859-1', 'UTF-8');   // "\xE9"
iconv('UTF-8', 'ASCII//IGNORE', 'aéb');            // "ab"
```

The crate registers 59 functions and the `MB_CASE_*` and `ICONV_MIME_DECODE_*`
constants. Not registered: `mb_send_mail` and the Oniguruma regex family
`mb_ereg*`. `mb_regex_encoding()` is kept as a setting only.

## Encodings

`mb_*` supports 48 of PHP 8.5's 79 encodings, under PHP's names and aliases:
the Unicode ones (UTF-8, UTF-16/32 and UCS-2/4 in both byte orders, with or
without a byte order mark), ASCII and 7bit/8bit, ISO-8859-1 to -10 and -13 to
-16, Windows-1251/1252/1254, KOI8-R/U, EUC-JP, SJIS, CP932, SJIS-win,
ISO-2022-JP, GB18030, CP936, BIG-5, EUC-KR, and the deprecated transfer
encodings BASE64, UUENCODE, HTML-ENTITIES and Quoted-Printable. Their names,
aliases and MIME names are in `src/encoding.rs`.

Not supported, so a `ValueError` like an unknown name: UTF-7, UTF7-IMAP,
eucJP-win, EUC-JP-2004, CP51932, JIS, ISO-2022-JP-MS, ISO-2022-JP-2004,
CP50220/1/2, the SJIS, UTF-8 and ISO-2022-JP mobile variants, SJIS-mac, SJIS-2004,
GB18030-2022, EUC-CN, HZ, EUC-TW, CP950, UHC, ISO-2022-KR, CP866, CP850 and
ArmSCII-8.

The case and width tables, the single-byte and CJK tables and the kana
mappings were generated by running PHP 8.5.12 over every code point
(Unicode 17), so they hold what PHP does, not what a Unicode library does.
Nothing calls PHP at run time. `mb_*` gives the same answers on every
platform.

## iconv and the platform

`iconv*` calls the operating system's iconv through `iconv-native`, as PHP
does: glibc on Linux, Apple's iconv on macOS. That makes Phera agree with PHP
on the same machine by construction, including the encodings and names only
the platform knows, which no pure Rust library could match on both. It also
means `iconv()` results can differ between Linux and macOS, as PHP's do.

- `//TRANSLIT` is not reproducible. glibc transliterates by the process's
  `LC_CTYPE`, which PHP sets to `C.UTF-8` at startup and Phera leaves at `C`,
  so `iconv('UTF-8', 'ASCII//TRANSLIT', 'é')` is `"e"` in PHP and `"?"` in
  Phera on Linux. Apple's iconv transliterates by the state of the process:
  the same call gives different strings under `php -r` and in a script file,
  and may succeed or fail depending on earlier conversions.
- From 64 KiB on, `iconv`, `iconv_strlen` and `iconv_substr` convert on
  Tokio's blocking threads, since a large conversion can take long (a
  megabyte to `//IGNORE` takes about a quarter of a second on macOS).
  `iconv_strpos`, `iconv_strrpos` and the MIME functions still convert on
  the request's worker thread.

## Differences from PHP

What Phera does differently on purpose or by necessity:

| What | PHP | Phera |
| --- | --- | --- |
| `mb_list_encodings()` | 79 names | the 48 supported, in PHP's order |
| `iconv(..., '...//TRANSLIT', ...)` | depends on locale and process state | the platform's iconv in the `C` locale |
| `mb_encode_mimeheader($s)` in Korean, Armenian or Simplified Chinese | ISO-2022-KR, ArmSCII-8, HZ | `ValueError`: those charsets are missing |
| `mb_encode_mimeheader($s, null, null)` | null is deprecated and means `""` | null means "not given" |

## Not done yet

- `mb_encode_mimeheader` folds encoded words, but long plain text only by
  breaking the line before it. PHP breaks at the last space that fits:
  `mb_encode_mimeheader(str_repeat('a ', 50))` is `"a a ... a\r\n a ..."` in
  PHP and `"\r\n a a ..."` in Phera.
- `iconv_mime_encode` folds between bytes, which can split a character
  across two encoded words; PHP folds between characters.
- `mb_get_info('illegal_chars')` is always 0; PHP counts the characters it
  could not convert.
- `"auto"` in an encoding list is always the detect order. In PHP it depends
  on the language (Japanese means ASCII, JIS, UTF-8, EUC-JP, SJIS).
- `mb_detect_encoding` uses PHP's scoring, but not all of its heuristics
  (byte order marks, ties).
- `mb_strcut` on ISO-2022-JP counts each character with its own escape
  sequences; PHP's byte budgets differ there.
- Malformed ISO-2022-JP, arbitrary invalid GB18030 sequences and malformed
  MIME words are only covered by the general matrices.
- `mb_convert_encoding` and `mb_convert_variables` leave objects and
  references inside arrays as they are.
- `mb_http_input` reports no input encoding: Phera does not translate request
  input. `mb_parse_str` uses PHP's defaults (`max_input_vars` 1000, `&`).
- `mb_output_handler` converts but ignores `$status` and sets no
  `Content-Type`.
- No `mbstring.*` or `iconv.*` ini settings.

## How it is verified

Every suite compares with real PHP 8.5 (`find_php()`): results, output,
warnings, notices and deprecations.

| Suite | Compared calls |
| --- | ---: |
| Every Unicode code point: case in eight modes, width, ord, chr, check (`tests/unicode.rs`) | 15,570,944 |
| Every representable character of 44 encodings, both ways (`tests/encodings.rs`) | 25,091,286 |
| Every two-byte string as UTF-8, four functions (`tests/invalid.rs`) | 262,144 |
| Scripts and invalid bytes × encodings × offsets (`tests/matrix.rs`) | 70,452 |
| Kana flags × encodings (`tests/kana.rs`) | 9,330 |
| Padding, entities, MIME, detection, iconv options (`tests/options.rs`) | 8,160 |
| Transfer encodings and their deprecations (`tests/transfers.rs`) | 1,605 |
| Every function with hostile arguments (`tests/matrix.rs`) | 1,239 |
| Settings, languages and mail defaults (`tests/options.rs`) | 306 |
| Encoding names and aliases (`tests/encodings.rs`) | 179 |
| 1 MB strings in six encodings, and through iconv (`tests/large.rs`) | 121 |
| By-reference results (`tests/request.rs`) | 9 |

Two kinds of case are compared in a weaker form, as `tests/support/mod.rs`
explains: `mb_list_encodings()` is PHP's list restricted to Phera's names,
and a `//TRANSLIT` result must be of the same kind, ASCII, with the same
diagnostics (on macOS a refusal counts as a result too). A literal passed to
a by-reference parameter gets the error Phera's VM raises at the call site.

`crates/runtime/tests/requests.rs` runs the functions in two requests to check
that settings do not leak between them.

## Speed

In-process, a 1 MB UTF-8 string of ASCII, Latin, Greek, Chinese and emoji,
median of seven runs of 30 calls:

| Function | Phera / PHP |
| --- | ---: |
| `mb_strlen` | 0.85 |
| `mb_substr` | 0.8 |
| `mb_strtoupper` | 1.2 |

`cargo run --release -p phera-ext-mbstring --example benchmark` reproduces
these. They measure the native function, not the VM.

## Regenerating the tables

The tables in `data/` come from PHP 8.5.12; `data/NOTICE` lists them.

```sh
cargo run -p phera-ext-mbstring --example generate        # case, width, single-byte, entities
cargo run -p phera-ext-mbstring --example generate -- cjk # EUC-JP, SJIS, CP932, ... tables
cargo run -p phera-ext-mbstring --example generate_gb     # GB18030-2000 corrections
cargo run -p phera-ext-mbstring --example generate_kana   # mb_convert_kana mappings
python3 examples/generate-rare.py ~/php-src               # mb_detect_encoding's rare characters
```

## Dependencies

- `encoding_rs`: GB18030, where PHP's 2000 mapping differs from it in 39
  places that `data/gb18030-patches.bin` corrects, and EUC-JP's three-byte
  characters.
- `base64`: BASE64 and the B scheme of MIME words.
- `iconv-native`: safe calls to the platform's iconv; no `unsafe` here.
- `tokio`: the blocking threads for large iconv conversions.
